DocIntel MVP Build Plan
========================

Goal
----
Build an AI research assistant that lets a user upload PDF documents, ask
questions about them, receive an answer grounded in the documents, and see the
source document and page numbers used for the answer. Groq provides the chat
model through its API, while ChromaDB handles local vector storage and local
embeddings.

MVP scope
---------
Included:
- PDF upload
- Text extraction with PyMuPDF
- Text chunking
- Local embeddings using ChromaDB's default embedding function
- Local ChromaDB vector storage
- Similarity search
- Answer generation with a Groq API chat model
- Source citations containing filename and page number
- FastAPI backend
- Streamlit frontend
- Basic tests and documentation

Not included yet:
- PostgreSQL or pgvector
- Redis or background workers
- Authentication and multiple users
- AWS, Azure, Kubernetes, or CI/CD
- MCP
- Complex agents and tool calling
- Hybrid search or reranking
- Web search
- DOCX, CSV, or other file types
- Production monitoring

Phase 0: Confirm the setup
--------------------------------
1. Confirm Python and Git are installed.
2. Create and activate the virtual environment:
   python3 -m venv .venv
   source .venv/bin/activate
3. Install dependencies:
   python -m pip install -r requirements.txt
4. Create a Groq account and obtain an API key.
5. Add the key to a local `.env` file:
   GROQ_API_KEY=your_key_here
6. Choose a currently available Groq chat model and add it to `.env`:
   GROQ_MODEL=your_model_name
7. Test the Groq API before writing application code.
8. Confirm that ChromaDB can initialize its default local embedding model.

Phase 1: Create the project structure
-------------------------------------
Create:
- app/main.py              FastAPI application and API routes
- app/config.py            Environment variables and application settings
- app/pdf_loader.py        PDF text extraction with page metadata
- app/embeddings.py        ChromaDB embedding configuration
- app/rag.py               Chunking, indexing, retrieval, and answer generation
- frontend/streamlit_app.py Streamlit user interface
- data/documents/          Uploaded PDF files
- chroma_db/               Local ChromaDB persistence directory
- tests/                   Automated tests
- .env.example             Example configuration
- .gitignore               Ignore secrets, virtual environment, data, and database
- README.md                Setup, usage, architecture, and limitations

Phase 2: Implement PDF ingestion
--------------------------------
1. Accept a PDF file from the API.
2. Save it under data/documents/.
3. Open the PDF with PyMuPDF.
4. Extract text page by page.
5. Preserve metadata for every page:
   - source filename
   - page number
6. Reject unsupported files and empty PDFs with clear errors.
7. Add a test using a small sample PDF.

Phase 3: Implement chunking
---------------------------
1. Split extracted page text into manageable chunks.
2. Start with a recursive character text splitter.
3. Use a chunk size around 800 to 1,000 characters.
4. Use an overlap around 100 to 150 characters.
5. Preserve the source and page metadata on every chunk.
6. Test that chunks are created and retain correct page metadata.

Phase 4: Implement embeddings and ChromaDB
------------------------------------------
1. Configure ChromaDB's default embedding function for local embeddings.
2. Create a persistent local ChromaDB collection.
3. Generate an embedding for each chunk.
4. Store each chunk, its embedding, and its metadata.
5. Use stable document IDs so re-uploading a file does not create unwanted
   duplicates.
6. Add a way to clear or rebuild the collection during development.
7. Test that an indexed document can be retrieved for a relevant query.

Phase 5: Implement retrieval
-----------------------------
1. Convert the user question into an embedding.
2. Search ChromaDB for the top-k relevant chunks.
3. Start with k=4 or k=5.
4. Return the chunk text and metadata.
5. Remove duplicate source/page citations.
6. Handle the case where no useful context is found.
7. Test retrieval with questions whose answers are known to be in the sample PDF.

Phase 6: Implement grounded answer generation
----------------------------------------------
1. Configure a Groq chat model using `GROQ_API_KEY` and `GROQ_MODEL`.
2. Build a prompt containing:
   - the retrieved context
   - the user question
   - grounding instructions
3. Instruct the model to answer only from the supplied context.
4. Instruct it to say that the answer is not available in the documents when
   the context does not contain the answer.
5. Generate the final answer.
6. Return the answer together with the retrieved source metadata.
7. Keep citations generated by the application rather than trusting the model
   to invent page numbers.
8. Test both a question with an answer and a question outside the document.

Phase 7: Build the FastAPI backend
----------------------------------
Implement these initial endpoints:

POST /documents/upload
- Accept one PDF.
- Extract, chunk, embed, and store it.
- Return filename, page count, and chunk count.

POST /query
- Accept a question.
- Retrieve relevant chunks.
- Generate a grounded answer.
- Return answer and citations.

GET /health
- Return a simple healthy response.

1. Add Pydantic request and response models.
2. Add clear HTTP errors.
3. Keep the core RAG logic separate from route functions.
4. Test endpoints with FastAPI TestClient.

Phase 8: Build the Streamlit frontend
--------------------------------------
1. Add a PDF uploader.
2. Add an upload/process button.
3. Display processing success or errors.
4. Add a question input and ask button.
5. Send requests to the FastAPI backend.
6. Display the answer.
7. Display citations in a readable format:
   [1] filename.pdf - Page 4
8. Display useful loading and error states.
9. Keep the UI simple until the complete workflow works.

Phase 9: Complete MVP testing
-----------------------------
1. Confirm the Groq API is available.
2. Start the FastAPI server.
3. Start Streamlit.
4. Upload a real technical PDF.
5. Ask a question with an obvious answer in the PDF.
6. Confirm the answer is based on the document.
7. Confirm page citations are displayed.
8. Ask a question not covered by the PDF.
9. Confirm the system says it does not know instead of guessing.
10. Test a multi-page PDF.
11. Test an invalid file and an empty PDF.
12. Test restarting the application and reusing the local ChromaDB data.

Phase 10: Documentation and MVP completion
-------------------------------------------
1. Write the exact setup commands in README.md.
2. Document the Groq API key and selected model configuration.
3. Add the application architecture diagram.
4. Explain the RAG pipeline in plain language.
5. Document the API endpoints.
6. Document known limitations.
7. Add screenshots or a short demo video later.
8. Add a final MVP checklist.

Recommended implementation order
--------------------------------
Build and test one vertical slice at a time:

1. PDF file -> extracted page text
2. Extracted text -> chunks with metadata
3. Chunks -> ChromaDB embeddings
4. Question -> retrieved chunks
5. Retrieved chunks -> grounded answer
6. RAG pipeline -> FastAPI endpoint
7. FastAPI endpoint -> Streamlit UI
8. Full workflow -> tests and README
